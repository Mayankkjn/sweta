Colour

A deep-forest primary ramp, a cool green-grey neutral ramp, and three semantic hues each paired with a tint. Components reference semantic tokens (--fy-text-heading), never raw primitives. Swatches marked added are not in the PDF and exist to give each status colour an AA-safe text variant.

Typography

One family, Poppins, in four weights. Sizes and weights match the PDF; line heights are proposed (1.25 headings, 1.4 subtitles, 1.5 body). Headings default to --fy-text-heading.

Space & shape

A 4px grid. Screens use a 16px side gutter (space-4) and 12px between stacked cards (space-3). Corners: 8px on controls, 12px on cards and list rows, 16px on sheets and panels.

Buttons

Full-width, 48px tall, 8px radius, label in Subtitle 1 (Semibold 16). Use one primary per screen, pinned to the bottom. Pair it with a secondary for a lesser action (“Edit All” over “Looks Good”).

Input fields

Outlined form fields: 40px tall, 1px border-default, 8px radius. The login flows use the filled 48px phone input instead. Label sits 8px above in Subtitle 3 (Medium 12). Values use Body 2. Focus turns the border green with a soft green ring. Errors turn border, value and helper text red.

Notes on the source PDF

Where the PDF was inconsistent, the tokens follow the rendered artwork rather than the labels.

Both “BG” swatches are labelled #02372F. The green one renders as #4C9B66 (same as success) and the light one as #F5F6F0. They are tokenised as bg-brand and bg-canvas.
“Subtitle 2” appears twice (Medium 16 and Medium 12). The 12px style is renamed subtitle-3. It is the field-label style.
Success tint is labelled #CCE6D4 but renders as #EEF7F1. The selected-chip fill also uses #EEF7F1, so both are kept: success-100 #CCE6D4 and success-50 #EEF7F1 (success-subtle).
Figma overrides the PDF measurements. Buttons and inputs use an 8px radius (the PDF looked like 6px). Cards use 12px and sheets 16px. The button gradient is #1F673F → #57A870 at 94°. Links use success-700 #236B42. The tokens now follow Figma.
Off-palette colours in Figma, mapped to tokens: card border #EDEDED → neutral-200, edit tag #F4F5EF → cream-50, legal text #546881 → neutral-500, T&C link #09A98B → success-700, video title #151A20 → neutral-600, success #4C9B67 → success-600. The Figma file has no colour variables, so every value is typed in by hand. Publishing these tokens as Figma variables would stop the drift.
Two typefaces leak into Figma text layers: “Cina GEO Test” (T&C line, bank names, “don’t allow”) and SF Pro (system keypad only). The components use Poppins throughout.
Token names now match Figma variables. The product pages use Figma variables Primary 100–600, Neutral 100–600, Success 50 / 600, Error 600, White and the effects Card shadow and Card Shadow light. The CSS tokens use the same numbers, so --fy-primary-400 is Figma’s Primary 400 (#03685A). The login pages don’t use these variables yet.
Figma text styles disagree with the PDF in two places. The Figma style “Body 2” is Medium 14/22, but the PDF says Regular 14. Line heights are 22px (14–16px text) and 28px (Heading 3). The tokens take the Figma line heights and keep the PDF weight for Body 2 until a designer decides which is right.
More off-palette values on the product pages: labels #8B8B8B → neutral-500, values #4A4A4A → neutral-600, positive returns #2F8F0D (4.15:1) → success-700 #236B42, “Learn more” #D19405 (2.6:1) → warning-700, slider track #E4F2E8 kept, chip fill #F3F3F3 → neutral-100. The ₹ sign uses “Inria Sans”, and the FIRE FAQ tiles use a serif face. Neither is in the brand fonts.
Repeated frames that should be Figma components: transaction row (~200 copies), breakdown row (178), FIRE card (153), skeleton (190), period chips, member switcher, holding card, asset row. Only “Primary button”, “BNB-14”, “Outgoing breakup”, “Total toggle”, “Edit value” and “Date selector” are real components today.
Not specified in the PDF, so these are proposed: line heights, the spacing scale, radii, shadows, focus rings, gradient angles and component heights. Heights and radii were measured from the artwork at a 360px mobile frame (48px buttons, 40px inputs, 6px corners).
